# STMGameBoy 개발 로드맵

## 목표

STM32F429I-DISC1에서 Peanut-GB로 내장 ROM을 실행하고, 조이스틱과 버튼으로 조작하며 LCD에 표시한다.
우선 게임을 실제로 구동하는 데 집중하고 터치 화면, 배율, 팔레트, 저장 기능은 이후 단계에서 추가한다.

## 현재 완료된 항목

- STM32CubeIDE 및 CubeMX 프로젝트 구성
- SDRAM 및 LTDC 초기화
- LCD 단색 출력 검증
- 조이스틱 ADC 입력 검증
- A, B, SELECT, START GPIO 입력 검증
- FreeRTOS `inputTask`, `displayTask` 분리
- `inputState` 기반 active-low 입력 비트마스크 및 동시 입력 처리
- 게임 내 조이스틱 및 버튼 조작 검증
- Peanut-GB 헤더 추가
- 게임 ROM을 `gb_rom.c`, `gb_rom.h`로 변환
- Peanut-GB ROM/RAM/에러 콜백 및 `gb_init()` 연결
- LCD 한 줄 출력 콜백 및 `gb_run_frame()` 연결
- Peanut-GB 게임 화면 출력 검증
- `inputState`를 Peanut-GB 조이패드에 연결
- 터치 컨트롤러용 I2C3 설정
  - PA8: I2C3 SCL
  - PC9: I2C3 SDA
  - 100 kHz, 7-bit addressing

## 1. 터치 통신 최소 검증

터치는 게임 실행에 필수는 아니지만 I2C 설정 직후 통신 여부만 확인해 두는 것이 좋다.

- STMPE811 칩 ID 읽기
- 터치 눌림 여부 확인
- 좌표 한 번 읽어 UART로 출력
- 인터럽트 없이 폴링 방식으로 검증

이 단계에서는 화면 배율 변경까지 구현하지 않는다. 칩 ID와 좌표가 정상적으로 읽히면 터치 하드웨어 검증은 종료한다.

## 2. Peanut-GB 실행부 연결

`task.c`에 최소한의 프런트엔드 코드를 추가한다. 현재 규모에서는 별도 파일을 더 만들 필요가 없다.

현재 구현된 항목은 다음과 같다.

- `struct gb_s` 에뮬레이터 인스턴스
- ROM 읽기 콜백
  - `gbRomData[address]` 반환
  - `gbRomSize` 범위 확인
- 카트리지 RAM 읽기 및 쓰기 콜백
  - 현재 ROM에 맞춰 32 KiB RAM 확보
- 에러 콜백
- `gb_init()` 호출
- 초기화 성공 여부와 ROM 이름 UART 출력
- LCD 한 줄 출력 콜백
- `gb_init_lcd()` 호출
- `gb_run_frame()` 호출

현재 코드는 프레임마다 `inputState`를 복사한 뒤 에뮬레이터를 실행한다.

Boot ROM은 필수가 아니다. Peanut-GB의 기본 초기 상태로 먼저 실행한다.

### 첫 번째 성공 기준

- `gb_init()`이 `GB_INIT_NO_ERROR`를 반환한다.
- `gb_run_frame()` 호출 후 멈추거나 오류에 빠지지 않는다.
- LCD에 게임의 첫 화면이 나타난다.

## 3. LCD에 네이티브 화면 출력

게임보이 원본 화면은 160 x 144이고 LCD는 240 x 320이다. 확대하지 않고 중앙에 배치한다.

- X 오프셋: `(240 - 160) / 2 = 40`
- Y 오프셋: `(320 - 144) / 2 = 88`
- Peanut-GB 픽셀의 하위 2비트를 4단계 RGB565 팔레트로 변환
- 기존 `LCD_Fill()` 색상 순환 테스트 제거

LTDC는 프레임버퍼를 계속 출력하므로 Peanut-GB의 LCD 콜백에서는 SDRAM 프레임버퍼 내용만 갱신하면 된다.

## 4. 입력을 Peanut-GB에 연결

`inputTask`는 물리 입력을 `inputState` 8비트 비트마스크로 변환한다. 버튼은 각각 독립적으로 처리하며 조이스틱의 X축과 Y축도 따로 판정하므로 버튼 조합과 대각선 입력을 지원한다.

매핑은 다음과 같다.

| 물리 입력 | Peanut-GB 입력 |
| --- | --- |
| 조이스틱 왼쪽 | `JOYPAD_LEFT` |
| 조이스틱 오른쪽 | `JOYPAD_RIGHT` |
| 조이스틱 위 | `JOYPAD_UP` |
| 조이스틱 아래 | `JOYPAD_DOWN` |
| A 버튼 | `JOYPAD_A` |
| B 버튼 | `JOYPAD_B` |
| SELECT 버튼 | `JOYPAD_SELECT` |
| START 버튼 | `JOYPAD_START` |

Peanut-GB의 조이패드는 active-low 방식이다. 기본값은 `0xFF`이고 눌린 버튼의 비트를 0으로 내린다.

`gb.direct`는 스레드 안전하지 않으므로 `inputTask`가 에뮬레이터 구조체를 직접 수정하지 않도록 한다.

- `inputTask`: 현재 입력을 `inputState`에 기록
- `displayTask`: 프레임 시작 전에 `inputState`를 `gb.direct.joypad`에 복사

8비트 값 하나만 공유하면 별도 큐나 뮤텍스 없이도 현재 MCU에서 충분히 단순하게 처리할 수 있다.

`displayTask`가 프레임 시작 전에 `gb.direct.joypad = inputState`로 현재 상태를 전달한다.

## 5. 프레임 실행과 속도 맞추기

`displayTask`가 에뮬레이터 실행과 화면 갱신을 함께 담당한다.

- 입력 상태 복사
- `gb_run_frame()` 호출
- 약 59.7 FPS에 맞춰 다음 프레임까지 대기
- 한 프레임 목표 시간: 약 16.74 ms

입력 복사와 프레임 실행은 연결되어 있다. 현재는 별도 지연 없이 실행하며, 실제 프레임 시간을 측정한 뒤 목표 속도에 맞게 보정한다.

입력 로그는 상태가 바뀔 때만 출력한다. 게임 구동 성능에 영향이 있으면 로그를 비활성화한다.

## 6. 터치로 화면 배율 전환

게임 실행이 안정된 다음 구현한다.

- 기본 화면: 160 x 144 중앙 표시
- 확대 화면: 240 x 216
- 터치가 눌리는 순간 배율 상태 전환
- 손을 계속 대고 있는 동안 반복 전환되지 않도록 눌림 에지와 간단한 디바운싱 적용

STM32 DMA2D는 임의 비율 확대 장치가 아니므로 1.5배 확대는 CPU 기반 최근접 보간으로 처리하는 편이 단순하다. 성능이 부족할 때만 변환 방식을 최적화한다.

## 7. 팔레트 변경

화면 출력과 배율 전환이 완료된 다음 추가한다.

- 4단계 RGB565 팔레트를 배열로 관리
- 기본 흑백 또는 녹색 계열 팔레트부터 적용
- 터치 영역 또는 START/SELECT 조합으로 팔레트 변경

팔레트 변경을 위해 별도의 물리 버튼을 추가할 필요는 없다.

## 8. 저장 데이터 처리

현재 ROM은 카트리지 RAM을 사용하므로 게임 실행을 위해 32 KiB RAM은 필요하다.

첫 단계에서는 MCU RAM에만 유지한다. 전원을 끄면 저장 데이터가 사라진다.

영구 저장이 필요해지면 다음 중 하나를 선택한다.

- 내부 Flash의 별도 섹터 사용
- 외부 저장장치 추가

내부 Flash 저장은 섹터 삭제 단위와 수명을 고려해야 하므로 최소 플레이 검증 이후로 미룬다.

## 9. 후순위 항목

다음 기능은 기본 게임 실행 후 시간이 남을 때 진행한다.

- 프레임 시간 측정 및 성능 최적화
- Release 최적화 적용
- 화면 tearing 개선
- 오디오 출력
- 저장 데이터 영구 보관
- 복수 ROM 선택
- 터치 메뉴

TouchGFX와 C++는 현재 목표에 필요하지 않다. Peanut-GB와 LCD 출력은 C만으로 완성할 수 있다.

## 권장 작업 순서

1. 게임 화면과 조작 동작 확인
2. 프레임 시간 측정 및 속도 조정
3. STMPE811 칩 ID와 좌표 읽기 검증
4. 터치 배율 전환
5. 팔레트 변경
6. 저장 및 오디오 검토

## 예상 소요 시간

| 작업 | 예상 시간 |
| --- | ---: |
| 터치 최소 검증 | 30분 ~ 1시간 |
| Peanut-GB 초기화 및 콜백 | 1 ~ 2시간 |
| 첫 화면 출력 및 디버깅 | 2 ~ 4시간 |
| 입력 연결 및 프레임 조정 | 1 ~ 2시간 |
| 터치 배율 및 팔레트 | 1 ~ 3시간 |

첫 플레이 가능 상태까지 약 5~8시간을 예상한다. ROM 호환성이나 화면 출력 문제가 생기면 추가 디버깅 시간이 필요할 수 있다.

## 최소 완료 조건

- ROM 초기화 성공
- 게임 화면 출력
- 방향키, A, B, SELECT, START 동작
- 약 60 FPS에 가까운 속도로 실행
- 장시간 실행 중 멈춤이나 메모리 오류 없음

배율, 팔레트, 터치 메뉴, 오디오, 영구 저장은 최소 완료 조건에 포함하지 않는다.
